# 2.2 Fundamentals of cryptography (2)

## RSA 算法的加密过程

1. 选择两个质数 p, q
2. 让这两个质数相乘 p * q，得到的结果是N（也就是用来计算余数的数字）
3. 欧拉函数 T = (p-1) * (q-1)
4. 选择接受者的公钥 E，公钥需要同时满足以下的条件，然后从中选择一个满足条件的数字作为公钥
   - 必须是质数
   - 1 < 公钥 E < T
   - 不是 T 的因子

5. 计算接收者的私钥 D
   - 私钥需要满足 (D * E) % T = 1

在通信的过程中，接受者的公钥 E 和所求得到质数 N 是对所有人公开的，信息接受者需要保密的只有私钥 D。

在信息发送的过程：发送方 (E(7), N(33))，接收方(D(3保密), N(33))

1. 例如发送者要发送三个数字 3，1，15，先根据公钥求幂
   - 3^7^ = 2,187
   - 1^7^ = 1
   - 15^7^ = 170,859,375   

2. 然后再对求幂之后的结果，通过N计算余数
   - 2187 % 33 = 9
   - 1 % 33 = 1
   - 170,859,375  % 33 = 27
3. 发送方将最后得到的9，1，27发送给接收方
4. 接收方在接收到数字之后，进行逆向计算。在这里首选需要使用 D 求幂
   - 9^3^ = 729
   - 1^3^ = 1
   - 27^3^ = 19,683
5. 然后对这三个结果求余
   - 726 % 33 = 3
   - 1 % 33 = 1
   - 19,683 % 33 = 15

最后的结果是一致的。

通常在现实中会将N设置的非常大，这样就会有非常多的p, q可以被选择，从而T的结果也会非常大。这样根据T选择出来的公钥E也可以有非常多的选择，从而即使我们对外公开N和E，暴力破解也需要很长时间。



# 1. CBC 加密过程

假设明文消息被分成多个固定长度 block：

```
M = M1 || M2 || M3 || ... || Mn
```

使用同一个密钥 `k`，并且需要一个初始化向量 `IV`。

CBC 加密公式是：

```
C0 = IV

C1 = Enc(k, M1 ⊕ C0)
C2 = Enc(k, M2 ⊕ C1)
C3 = Enc(k, M3 ⊕ C2)
...
Cn = Enc(k, Mn ⊕ Cn-1)
```

最后发送：

```
IV || C1 || C2 || C3 || ... || Cn
```

也就是说，CBC 加密不是直接把每个明文块单独加密，而是：

```
当前明文块 XOR 前一个密文块 → 再加密
```

第一个明文块没有“前一个密文块”，所以用 `IV` 代替。

------

## CBC 加密例子

假设有 3 个明文块：

```
M1, M2, M3
```

加密过程如下：

```
C0 = IV

C1 = Enc(k, M1 ⊕ IV)

C2 = Enc(k, M2 ⊕ C1)

C3 = Enc(k, M3 ⊕ C2)
```

最终密文是：

```
IV, C1, C2, C3
```

这里的关键是：
 `C2` 不仅和 `M2` 有关，也和 `C1` 有关；而 `C1` 又和 `M1`、`IV` 有关。所以后面的密文块会受到前面明文块的影响。

这也是为什么 CBC 可以隐藏 ECB 中“相同明文块产生相同密文块”的问题。Tutorial 中也展示过，CBC 可以让相同 salary 得到不同 ciphertext，从而防止相同数据被识别。

------

# 2. CBC 解密过程

CBC 解密是加密的反过程。

接收方收到：

```
IV || C1 || C2 || C3 || ... || Cn
```

解密公式是：

```
M1 = Dec(k, C1) ⊕ IV

M2 = Dec(k, C2) ⊕ C1

M3 = Dec(k, C3) ⊕ C2

...

Mn = Dec(k, Cn) ⊕ Cn-1
```

也就是：

```
先解密当前密文块 → 再 XOR 前一个密文块
```

对于第一块，前一个密文块不存在，所以用 `IV`。

L2 课件中也提到，第一个 block 解密后需要和 IV 做 XOR；后续 blocks 则和 previous ciphertext block 做 XOR。

------

## CBC 解密例子

如果密文是：

```
IV, C1, C2, C3
```

那么：

```
M1 = Dec(k, C1) ⊕ IV

M2 = Dec(k, C2) ⊕ C1

M3 = Dec(k, C3) ⊕ C2
```

所以 CBC 解密必须保留所有密文块。因为要解开 `M2`，你不仅需要 `C2`，还需要 `C1`；要解开 `M3`，你不仅需要 `C3`，还需要 `C2`。

这就是你笔记中说的：CBC 加密保留了“解密线索”。你的笔记里也说明，CBC 模式中每个明文块加密后的密文块都会被保留并发送给接收方，所以信息没有丢失。

# 3. CBC-MAC 生成 tag 的过程

CBC-MAC 的计算过程看起来很像 CBC 加密，但是目的完全不同。

CBC 加密的目的是：

```
让别人看不懂消息内容
```

CBC-MAC 的目的是：

```
让接收方确认消息没有被篡改
```

假设消息是：

```
M = M1 || M2 || M3 || ... || Mn
```

CBC-MAC 一般使用固定 IV，例如：

```
C0 = 0
```

然后计算：

```
C1 = Enc(k, M1 ⊕ C0)

C2 = Enc(k, M2 ⊕ C1)

C3 = Enc(k, M3 ⊕ C2)

...

Cn = Enc(k, Mn ⊕ Cn-1)
```

但是注意：CBC-MAC **不输出所有 C1, C2, ..., Cn**。

它只输出最后一块：

```
tag = Cn
```

你的笔记和课件都强调：如果只输出最后一个密文分组，就得到 basic CBC-MAC model；中间加密结果不输出，只输出最后的 `Cl`，因此最后一块可以作为整个消息的 tag。

------

## CBC-MAC 生成 tag 例子

假设消息有 3 块：

```
M1, M2, M3
```

CBC-MAC 计算：

```
C0 = 0

C1 = Enc(k, M1 ⊕ C0)

C2 = Enc(k, M2 ⊕ C1)

C3 = Enc(k, M3 ⊕ C2)
```

最终：

```
tag = C3
```

发送方发送：

```
M, tag
```

也就是：

```
M1 || M2 || M3, C3
```

------

# 4. CBC-MAC 如何确认消息没有被篡改

假设 Alice 发给 Bob：

```
M, tag
```

Bob 收到后不会“解密 tag”。
 Bob 会用同一个密钥 `k`，对收到的消息 `M` 重新做一遍 CBC-MAC。

过程如下：

```
收到：M1, M2, M3, tag

重新计算：

C0' = 0

C1' = Enc(k, M1 ⊕ C0')

C2' = Enc(k, M2 ⊕ C1')

C3' = Enc(k, M3 ⊕ C2')

tag' = C3'
```

然后比较：

```
tag' == tag ?
```

如果相等：

```
accept
```

说明消息大概率没有被篡改。

如果不相等：

```
reject
```

说明消息或 tag 至少有一个被改过。

课件中也明确写到，CBC-MAC 的 verification 是通过重新计算结果完成的，而不是通过解密恢复原文。

------

## 为什么被篡改后能发现？

因为 CBC-MAC 是链式结构。

假设原消息是：

```
M1, M2, M3
```

原本 tag 是：

```
tag = C3
```

如果攻击者把 `M2` 改成 `M2*`，那么重新计算时：

```
C1' = Enc(k, M1 ⊕ C0)
C2' = Enc(k, M2* ⊕ C1')
C3' = Enc(k, M3 ⊕ C2')
```

因为 `M2` 改了，所以 `C2'` 会变。
 因为 `C2'` 变了，所以 `C3'` 也会变。
 最后：

```
tag' ≠ tag
```

所以 Bob 会 reject。

这就是 CBC-MAC 的核心思想：**任何一个 block 被改动，都会影响后面的链式结果，最终影响最后的 tag。**
